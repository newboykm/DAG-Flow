# Skill: review

审查待提交改动，标记问题。只读。

## 工作方式
1. 拿到当前 diff（默认分支 diff）。
2. 逐处检查：正确性、安全、缺测试、隐藏行为变化、无用改动。
3. 输出：verdict（结论）+ 逐条问题（文件:行号 + 说明）。
4. 只报告、不改代码；哪些要改由用户决定。
5. 改动越大越要细：涉及 auth、输入解析、文件 IO、外部请求的改动重点看。

## 停手 / 报告
- 结论要能直接指导下一步（“可以合”“先修 A 再合”“不要合”）。
- 不提主观喜好，只提可论证的问题。
